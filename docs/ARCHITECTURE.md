## Проекты

### `UniversalSearchLauncher.Core`

Платформенно-независимая логика:

- модели `AppEntry`, `FileEntry`, `SearchResult`, `Settings`, `UsageInfo`;
- `FuzzyMatcher` — нормализация, токенизация, точное/префиксное/подстрочное/acronym/fuzzy/typo-ранжирование;
- `PreparedQuery` — предварительно подготовленный запрос (нормализация выполняется один раз на нажатие);
- `AppSearchEngine` — ранжирование приложений с учётом usage/pins;
- `FileSearchEngine` — параллельный поиск по неизменяемому массиву индекса с ограниченным top-N;
- `FileIndexScanner` — обход выбранных папок, ограничения, отмена, исключения;
- `ExclusionSet` — сегменты папок, расширения, маски;
- `QueryIntent` — распознавание URL/домена и построение URL поисковых систем.

### `UniversalSearchLauncher`

WPF-приложение и Windows-интеграция:

- `LauncherWindow` — компактное окно без рамки, `AllowsTransparency`, glass-стиль, SizeToContent, анимации, keyboard-first;
- `SettingsWindow` — все настройки, захват горячей клавиши, папки, исключения, история;
- `LauncherViewModel` — состояние интерфейса, отмена поиска, фильтры, выбор, уведомления;
- `SearchService` — объединение провайдеров и групп;
- `AppIndexService` — меню «Пуск», `Get-StartApps`, COM `IShellLinkW`, кэш;
- `FileIndexService` — фоновые пересканирования, watchers, SQLite-кэш;
- `StorageService` — персистентность через системную `winsqlite3.dll`;
- `HotkeyService` — `RegisterHotKey`/`UnregisterHotKey`, обработка конфликтов и восстановление;
- `FullscreenDetector` — определение полноэкранного foreground-окна по `SHQueryUserNotificationState`, геометрии монитора и стилям окна;
- `TrayService` — `NotifyIcon` с тёмным контекстным меню;
- `ShellService` — запуск `.exe`, `.lnk`, UWP через `shell:AppsFolder`, открытие файлов/папок, `explorer /select`;
- `IconService` — извлечение shell-иконок с ограниченным кэшем;
- `ThemeService` — системная/тёмная/светлая тема;
- `StartupService`, `UpdateService`, `SingleInstanceService`, `WindowPlacement`.

### `UniversalSearchLauncher.Tests`

Консольный test harness без внешних test-framework-пакетов. Проверяет core-логику и производительность.

## Поток поиска

1. `LauncherViewModel.Query` меняется на UI-потоке.2. Предыдущий `CancellationTokenSource` отменяется.
3. `SearchService.SearchAsync` разбирает запрос:
   - пустой запрос → список недавних/закреплённых приложений;
   - URL/домен → один результат «Открыть сайт»;
   - обычный текст → параллельно приложения, файлы и интернет.
4. Приложения и интернет отдаются частичным снимком; файлы — финальным.
5. `LauncherViewModel` применяет фильтр категории, сохраняет выбранный ключ, строит элементы списка с групповыми заголовками.
6. Устаревшие результаты не применяются: проверяется поколение запроса и актуальность CTS.

## Ранжирование

Для каждого кандидата:

- поля приложения: название, имя `.exe`, имя ярлыка, дополнительные ключевые слова;
- поля файла: имя, родительская папка, расширение (нормализованная строка строится один раз);
- нормализация: Unicode FormD, удаление диакритики, `ё→е`, camelCase-разбиение, разделители;
- уровни совпадения:
  1. полное равенство;
  2. точное слово;
  3. начало слова;
  4. подстрока;
  5. акроним (начало/конец инициалов);
  6. subsequence-fuzzy;
  7. Levenshtein-опечатки;
- многословный запрос требует совпадения всех токенов, даёт бонус за общий фрагмент и порядок слов;
- бусты: закрепление (+200), частота запусков (логарифмически до +130), недавность (до +50), свежесть файла, приоритеты категорий.

Группы затем упорядочиваются по пользовательским приоритетам (по умолчанию: приложения → файлы → интернет; при равном приоритете порядок категорий фиксирован).

## Индексирование файлов

- Сканирование выбранных корней в отдельном фоновом Task с пониженным приоритетом потока.
- `AttributesToSkip`: System, ReparsePoint, Temporary; защита от циклических junction-ссылок.
- Пользовательские исключения проверяются до добавления и до спуска в папку.
- Жёсткий лимит количества элементов (`FileIndexMaxEntries`, по умолчанию 250 000).
- Снимок индекса — неизменяемый массив; поиск не блокирует пересканирование.
- `FileSystemWatcher` на локальных корнях + debounce 6 секунд, периодическое обновление (по умолчанию 15 минут).
- Кэш индекса записывается в SQLite одной транзакцией в фоне. UI не ждёт записи: история, запуски и закрепления пишутся асинхронно.
- При старте сначала загружается кэш, затем запускается фоновое обновление.

## Хранение

SQLite доступен через `winsqlite3.dll` — компонент Windows 10/11. Это позволяет не включать сторонние native-библиотеки и сохранить self-contained сборку компактнее.

Таблицы:

- `file_index` — кэш файлового индекса;
- `history` — запросы (с ограничением 100 строк);
- `usage` — количество и время запусков;
- `pins` — закреплённые элементы;
- `meta` — корни индекса, время, последний выбранный результат.

Настройки хранятся отдельно в `settings.json` для простого резервного копирования и восстановления.

## Производительность и отмена

- Нормализация названий файлов выполняется при индексации, а не при каждом запросе.
- Запрос подготавливается один раз (`PreparedQuery`).
- Файловый поиск параллелится по диапазонам с ограниченным top-N (без сортировки всего индекса).
- Все устаревшие запросы отменяются через `CancellationToken`.
- UI не делает файловых/сетевых операций; иконки извлекаются в кэш, тяжёлые операции уходят в Task Pool.
- Окно не отображается на панели задач (`ShowInTaskbar=False`), приложение работает в трее.

## Безопасность

- Установка per-user, без запроса UAC по умолчанию.
- Zip-распаковка установщика проверяет защиту от path traversal.
- Запуск приложений/файлов — через оболочку Windows.
- Приложение не выполняет произвольные команды из строки поиска, только открывает URL, приложения и файлы.
- Внешние данные (web search URL, update manifest) не исполняются как код.
- Журнал не содержит содержимого файлов и токенов.

## Расширение

Новый провайдер поиска реализуется как метод, возвращающий `SearchResult`, и подключается в `SearchService`. Категории и действия заданы enum-моделями, поэтому UI автоматически отобразит новую группу при добавлении соответствующей обработки.
