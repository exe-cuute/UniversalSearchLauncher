# Проверка приложения

## Автоматические тесты

```powershell
dotnet run --project tests\UniversalSearchLauncher.Tests\UniversalSearchLauncher.Tests.csproj -c Release
```

Покрытие:

- fuzzy-совпадения: точное, префикс, подстрока, акроним, опечатки, несколько слов;
- приоритет точного слова над префиксом и подстрокой;
- boost закреплённых и часто используемых приложений;
- URL: домены, localhost, пути Windows, имена файлов, поисковые URL Google/Bing/DuckDuckGo;
- исключения: сегменты, расширения, маски имён и путей;
- сканер файлов: папки, корень, лимит, исключения, поиск по результату;
- поиск по имени, папке и расширению;
- нормализация и клонирование настроек;
- производительность: 100 000 файлов, запрос с двумя токенами.

Ориентир на тестовой машине: **61 проверка, 100k-файловый запрос ~55–60 мс**.

## Ручной чек-лист

1. **Горячая клавиша**
   - Нажать `Alt+Space` в другом приложении — окно появляется по центру экрана и получает фокус.
   - Нажать ещё раз — окно скрывается.
   - `Esc` — окно скрывается.
   - Открыть настройки, сменить комбинацию, сохранить, проверить новую.
   - Задать занятую комбинацию — увидеть сообщение, старая продолжает работать.

2. **Полноэкранный режим**
   - Выключить «Показывать поверх полноэкранных приложений».
   - Запустить полноэкранную игру/видео; нажать `Alt+Space` — окно не появляется.
   - Открыть поиск из трея — окно появляется (ручное действие).
   - Включить опцию и повторить: `Alt+Space` открывает поиск поверх полного экрана.
   - Проверить обычное максимизированное окно: оно не должно блокировать лаунчер.

3. **Поиск**
   - `chr` → Google Chrome (если установлен) в категории «Приложения» первым.
   - `down` → папка Downloads.
   - `doc` → файлы/папки с совпадением.
   - `погода завтра` → интернет-поиск.
   - `github.com` → единственный результат «Открыть github.com».
   - Ввести несколько слов через пробел.

4. **Навигация**
   - `↓`/`↑` меняют выделение, строка поиска сохраняет текст.
   - `Enter` открывает приложение/файл/браузер.
   - `Tab` и `Shift+Tab` переключают «Все → Приложения → Файлы → Интернет».
   - Правый клик: открыть, открыть расположение, скопировать, закрепить.

5. **Файлы**
   - Открыть документ, папку, показать файл в проводнике.
   - Переименовать/создать файл в индексируемой папке — через несколько секунд он появляется в поиске.
   - Добавить/удалить папку в настройках, сохранить, дождаться переиндексации.
   - Проверить исключение `node_modules`/`.tools`.

6. **Настройки**
   - Тёмная/светлая/системная тема.
   - Поисковик Google/Bing/DuckDuckGo.
   - Количество результатов 4–15.
   - Приоритеты категорий.
   - Очистка истории (в лаунчере и в настройках).
   - Автозапуск: включить/выключить, проверить запись в `HKCU\...\Run`.
   - «Проверить обновления» без URL и с локальным/тестовым манифестом.

7. **Фон и завершение**
   - Закрыть окно поиска — приложение остаётся в трее, на панели задач его нет.
   - Меню трея: «Открыть поиск», «Настройки», «Проверить обновления», «Выход».
   - Выход завершает процесс, освобождает горячую клавишу и иконку трея.
   - Запустить второй экземпляр — новый процесс не появляется, первый активируется.

8. **Установка**
   - Запустить Setup, изменить папку, проверить ярлыки и автозапуск.
   - Запустить установленное приложение, проверить горячую клавишу и трей.
   - Запустить деинсталлятор, проверить удаление файлов, ярлыков, записи автозапуска и записи в списке приложений.
   - Проверить сохранение пользовательских данных при выборе «Нет» на вопрос об удалении настроек.

## Диагностика

- Журнал: `%LocalAppData%\UniversalSearchLauncher\logs\app.log`.
- Ошибки установщика: `installer.log` рядом с Setup, в `%LocalAppData%\UniversalSearchLauncher` или во временной папке.
- Настройки: `%LocalAppData%\UniversalSearchLauncher\settings.json`.
- Индекс/история: `%LocalAppData%\UniversalSearchLauncher\data\index.db`.
- Изолированный профиль для отладки: переменная окружения `USL_DATA_DIR` указывает на альтернативный каталог данных.
